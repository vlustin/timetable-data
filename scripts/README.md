# Парсер МИИТ

## Актуальный каталог групп

`miit_groups.py` читает официальную страницу `/timetable`: заголовок института/академии, раздел курса, ссылки на группы, включая выпадающие списки. Префиксы названий групп не используются для определения принадлежности. Сокращения и полные названия берутся из заголовков; стабильный `instituteId` получается транслитерацией официального HTML ID подразделения.

```sh
python3 scripts/miit_groups.py --report moscow-rut-miit/catalog-changes.json
```

Результат — `moscow-rut-miit/groups.json` версии 2 с массивами `institutes` и `groups`. Порядок институтов соответствует официальному каталогу, курсы идут по возрастанию, группы сортируются естественно. Отчёт содержит `added`, `removed`, `renamed` и `orphanTimetableIds`. Файлы расписаний физически не удаляются. При противоречивой принадлежности, неизвестном разделе курса или неполном разборе ссылок индекс не перезаписывается.

## Полная загрузка расписаний

Канонический `moscow_rut_miit_unified_parser.py` сохраняет исходный JSON-адаптер, события, отмены/замены, retry/timeout и smart weeks; дополнительно читает актуальные HTML-таблицы двух недель. Датированные занятия из «Разового» периода сохраняются в `events` с точными датами. По умолчанию используются типы источника 1, 2 и 4; числовые типы не служат признаком категории занятия. Период выбирается по текущей московской дате, без подмены занятий летней сессией. Если опубликован только будущий период, сохраняются его фактические даты и `meta.scheduleStatus=upcoming`; приложение показывает срок действия. Если источник содержит только истёкшие периоды, файл не перезаписывается и группа попадает в отчёт ошибок.

```sh
python3 scripts/moscow_rut_miit_unified_parser.py --all --workers 4 --delay 0.5
python3 scripts/moscow_rut_miit_unified_parser.py --group-id 193600
python3 scripts/moscow_rut_miit_unified_parser.py --retry-failed --workers 4
python3 scripts/moscow_rut_miit_unified_parser.py --all --from 2026-09-01 --to 2027-01-04 --types 1,2,4 --no-smart-weeks
```

`--workers` ограничен четырьмя запросами групп одновременно, по умолчанию один. `--timeout` и `--retries` задают таймаут и число попыток. Каждый JSON заменяется атомарно только после успешного разбора. `parse-report.json` перечисляет успешные файлы текущего запуска, ошибки, недостающие ID и устаревшие файлы; при ошибках программа завершает работу с ненулевым кодом. Наличие старого файла не считается успешной загрузкой. `--retry-failed` повторяет только недостающие группы после полного запуска и объединяет подтверждённые результаты; `runRequestedGroups` и `runSuccessfulFiles` показывают отдельный повторный проход.

## Вспомогательный адаптер регулярных занятий

`parse_miit.py` получает актуальное **периодическое расписание занятий** с официальной страницы группы. Python 3.9+; сторонние библиотеки не нужны.

```sh
python3 scripts/parse_miit.py --group СЖД-441
python3 scripts/parse_miit.py --group СЖД-341 --group СЖД-441
python3 scripts/parse_miit.py --all
```

Выбор периода происходит строго по опубликованной подписи «Периодическое» и дате его начала. Если есть только сессия или будущий период, программа сообщает об ошибке. Числовой параметр `type` берётся из ссылки сайта: его нельзя считать постоянным признаком экзаменов или занятий. Срок действия читается из текста «Расписание действует» и сверяется с выбранной ссылкой, I и II недели — из таблиц `week-1` и `week-2`. Мобильная копия расписания не разбирается, чтобы избежать дублей. Несколько занятий в одной ячейке сохраняются раздельно со своими преподавателями и аудиториями; вложенные ссылки и выделения в названиях предметов поддерживаются.

Результат записывается в `moscow-rut-miit/timetables/<groupId>.json`. I неделя — `lessons.odd`, II — `lessons.even`; `semester.startDate` обозначает начало первой учебной недели, календарный расчёт нужно привязывать к её понедельнику. ФИО, адреса, аудитории и подгруппы сохраняются раздельно.

Этот парсер пока обновляет регулярные занятия МИИТ. Датированные экзамены/консультации и СПбГУ требуют отдельных адаптеров. Летние события из прежнего JSON не переносятся в новый семестр. При отсутствии действующего периода, пустых таблицах, изменении структуры страницы или сетевой ошибке существующий JSON сохраняется, программа возвращает ненулевой код и сообщает об ошибке. Перед полной выгрузкой проверьте несколько групп; `--all` выполняет запросы последовательно с паузой.

Офлайн-проверка сохранённой страницы:

```sh
python3 scripts/parse_miit.py --group СЖД-441 --html /path/to/page.html --date 2026-10-05 --output /tmp/miit-check
python3 -m unittest discover -s scripts -p 'test_*.py'
```

`--date YYYY-MM-DD` задаёт дату, на которую должно действовать расписание; без этого параметра используется текущая московская дата. Проверка действует и для сохранённого HTML. Неизвестные группы и неверная дата приводят к ошибке до начала загрузки. `--group` и `--all` нельзя использовать вместе. JSON записывается в UTF-8 с атомарной заменой после успешного разбора.

В локальном `timetable-web` свежие JSON читаются из соседнего репозитория `timetable-data`. На опубликованном сайте источником остаётся GitHub; обновление там появится после отдельно запрошенной публикации файлов данных.
